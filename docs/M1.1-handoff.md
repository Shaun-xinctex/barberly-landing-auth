## 工作方式（重要，會影響效率）

**本機 shell（device_bash）不能用** —— 9/8 的 Windows 更新讓 Claude 的工作區掛載不到資料夾。改用：
- 讀檔：`device_stage_files`，或直接從 GitHub 淺 clone（`--depth 1 --filter=blob:none`）到雲端沙箱讀。
- 寫檔：`device_commit_files` 寫進資料夾。

**`.claude` 資料夾不可寫** —— 遠端工具拒絕。要更新技能得先寫到中繼資料夾（例如 `_skills-m1.2`），再請使用者在 PowerShell 複製過去。

**push 由使用者自己跑**（git proxy 不允許這個 session 對此 repo 寫入）：

```powershell
cd "C:\Users\skywa\barber-booking-platform"
git add -A
git commit -m "..."
git push origin main
```

**不要 force push / 改寫已發布歷史。**

**雲端沙箱網路受限** —— `supabase.co`、`fonts.googleapis.com` 被 egress policy 擋住（403）。要打線上服務用內建瀏覽器，不要用沙箱 `curl` 然後誤判成服務掛掉。

**沙箱跑不了 `npm ci` / type-check** —— 驗證靠靜態檢查 + Vercel build log。注意 `vite build` 只做 type-strip，綠燈不等於型別正確。

**AWS 連接器以 root 身分在跑** —— 帳號沒有 root access key（是連接時的 root 登入工作階段）。已知、已決定先不處理。root 也**沒有開 MFA**。IAM 使用者 `admin-for-cowork`、`admin-for-project-1-barber-booking-platform-001` 都有 AdministratorAccess 金鑰。

## M1.2 的地基已經備好

M1.2 是**顧客端**：瀏覽所有理髮師、理髮師詳細頁（含作品照輪播）、彈出對話框挑服務 + 時段下訂（不含付款）。

已就緒的東西：`barbers_public` view（公開瀏覽用、無敏感欄位）、`services.required_slots`（一次預約要佔幾個連續時段）、`bookable_slots` 的純時間窗設計、`barber_photos` + 公開 bucket（詳細頁的相簿）、`platform_settings.slot_minutes`。

課程規範提醒（來自 `supabase-best-practice`）：

- 預約橫跨 **N = `service.required_slots`** 個連續時段，**不要**用 `ceil(duration/30)` 算。
- 佔用關係放 **`booking_slots`** join 表，`UNIQUE(slot_id)` 是防重複預約的結構性保證；取消預約要**刪掉** `booking_slots` 列（free-on-cancel）。
- 時段是否可預約用**反向 join 推導**：`not exists (select 1 from booking_slots bs where bs.slot_id = s.id)`。`bookable_slots` 永遠沒有 status 欄位。
- `bookings` **沒有 `barber_id`**（透過 `service_id -> services.barber_id` 取得），也**沒有 `start_slot_id`**（開始時間是 join 後的 `MIN(starts_at)`，由 `bookings_with_start` view 提供）。
- `bookings.status` 只有三態：`pending_payment | paid | cancelled`。
- 每次 migration 的標準順序：**`apply_migration` → `get_advisors` → `generate_typescript_types`（要自己寫檔）→ 才寫 UI**。
